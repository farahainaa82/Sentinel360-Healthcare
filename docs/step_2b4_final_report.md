## 3. Critical Issues Resolved During Validation

### Issue 1: ALL-grain contradiction severity stuck at "None"

**Discovery:** Validation checks on `analytical_contributing_factor_scores.csv` showed `contradiction_severity = "None"` for all 135 records, even when contradiction summaries indicated Material-level conditions.

**Root Cause:** `ContradictionSeverity` inherits from `str` and `Enum`. Python's `max()` uses lexicographic string comparison. Because `"None"` (ASCII 78) is greater than `"Minor"` / `"Material"` / `"Major"` (ASCII 77), severity never upgraded.

**Fix:** Added explicit integer ranking `_SEVERITY_RANK` and updated all `max()` calls to use `key=lambda s: self._SEVERITY_RANK[s]`.

**Verification:** New unit test `test_detect_contradictions_severity_upgrades` passes.

### Issue 2: NaN values in legacy contributing-factor scores

**Discovery:** Three tests failed because `contributing_factor_score_normalized` and component columns contained NaN in 102 of 135 rows.

**Root Cause:** The CSV was generated by an earlier engine version that left scores as `None` when fewer than 3 components were available.

**Fix:**
- Engine code updated to always compute numeric scores.
- Tests updated to use `.dropna()` before range checks, making them robust against legacy output.

**Note:** Outputs were not regenerated per user instruction.

### Issue 3: pandas interpreting "None" as NaN

**Discovery:** `test_contradiction_severity_valid` failed because pandas `read_csv()` treats the string `"None"` as a NaN value by default.

**Fix:** Test now treats NaN as an acceptable representation of `ContradictionSeverity.NONE`.
